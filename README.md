# musid-dli

[![CI](https://github.com/emoeem/musid-dli/actions/workflows/ci.yml/badge.svg)](https://github.com/emoeem/musid-dli/actions/workflows/ci.yml)

Independent Rust music metadata and provider aggregation library.

musid-dli is not an audio player or decoder. It returns stream metadata (URL, headers, quality, expiry and fallback URLs) to the host application. VoiceFox continues to use lx-player + libmpv2.

## Boundaries

- Online providers: search, stream resolution, lyrics, playlists, albums, artists, charts, links and authentication.
- Local library: incremental directory scanning (per-file fingerprints plus directory signatures with an explicit force contract for hosts without a recursive watcher), streaming per-entry output with cancel/progress/concurrency limits, a failure ledger, duplicate/missing/corrupt diagnostics, metadata normalization with missing-tag fallbacks, lyrics reads (embedded plus sidecar .lrc), cover reads with a validated cache (optional local-cover feature), atomic tag writes, and an optional file-change event stream (optional local-watch feature); separate from online providers.
- Format handlers: CUE sheets (multi-track metadata splitting, GB18030/legacy-sheet fallbacks) and NCM containers (opt-in ncm feature, separately audited upstream).
- Download: separate optional service; keep VoiceFox downloader until parity.
- Playback/DSP/output: out of scope.

## Current bootstrap

The initial public models, capability-specific provider traits, registry, concurrent search aggregation, conservative deduplication, cross-provider match ranking, ordered stream fallback with circuit-breaker health tracking, quality-scoped expiry-aware stream cache, secure session persistence, separate local-library and container-handler interfaces, and lyrics-helper normalization are in place. An optional RustyPipe YouTube Music adapter compiles for search and stream URL resolution. An optional NetEase adapter now implements search, quality-fallback stream resolution, lyrics, cookie-backed session status, QR login (key generation + status polling) and registry registration. Playlists (categories, hot lists, search, detail, tracks), albums, artists, charts and share-link resolution are implemented and live-verified; user playlists require an authenticated session; parsing of the playlist/album/artist/toplist/legacy-song-detail responses is pinned by offline fixtures (tests/fixtures/netease, reconstructed shapes: see tests/fixtures/netease/README.md). An optional QQ Music adapter implements signed search, song detail, stream URL resolution (vkey ladder), lyrics, playlists (categories, lists, search, detail, user lists), albums, charts, song/playlist/album link resolution, QQ and WeChat scan login and session status; playable stream URLs require a logged-in session cookie; parsing of the search/song-detail/stream-vkey/lyric/playlist/album/chart responses is pinned by offline fixtures (tests/fixtures/qqmusic, reconstructed shapes: see tests/fixtures/qqmusic/README.md). Optional Kugou and Bilibili adapters implement search, lyrics/word timing (KRC), QR scan login and stream resolution; Kugou adds playlists, charts, albums, artists and link resolution (pinned by offline fixtures in tests/fixtures/kugou) and Bilibili adds WBI-signed DASH audio, charts (fixture-verified, live path unverified) and favorites (pinned by offline fixtures in tests/fixtures/bilibili). Provider evaluation verdicts for the remaining platforms live in docs/PROVIDER_EVALUATION.md. An optional Kuwo adapter implements anonymous search, lyrics (yeelion-XOR plus GB18030, plus word-timed lrcx lyrics that stay fixture-verified only: no live lrcx capture exists), mobile stream resolution with paid-song placeholder rejection, web-signed lossless streams, playlists (categories, hot ladder, per-tag lists, keyword search, paginated detail), charts, albums, song/playlist share-link resolution (song links resolve metadata-only through the songinfoandlrc route; fixture-pinned, the live link probe stays unverified) and cover URL resolution over a two-tier signed/anonymous fallback (pinned by offline fixtures in tests/fixtures/kuwo); the web-signed lossless tier itself stays unverified until a lossless-entitlement account session is available (human check, docs/HUMAN_TEST_CHECKLIST.md). An optional Migu adapter implements signed search, TEA-decrypted MRC word-timed lyrics, anonymous stream resolution with served-size quality correction, playlists, charts and albums (metadata derived from the anonymous queryAlbumSong track list; pinned by offline fixtures in tests/fixtures/migu). An optional Jamendo adapter (CC catalog) implements signed search with embedded stream URLs (pinned by offline fixtures in tests/fixtures/jamendo; the fixture batch's own anonymous smoke run failed at the endpoint, so the live path stays unverified at slice level). An optional Apple Music adapter implements search, 30-second preview streams (full tracks are DRM), plain-text lyrics and containers (parsing pinned by offline fixtures in tests/fixtures/apple). An optional 5sing adapter implements search, three-tier stream URLs and LRC lyrics (parsing pinned by offline fixtures in tests/fixtures/fivesing). An optional Qianqian adapter implements signed search, anonymous stream resolution over the tracklink rate ladder (full files for free tracks with size/md5/expiry; VIP tracks answer path-less metadata anonymously and resolve to NotFound), plain LRC lyrics, playlists (categories, category lists, detail with tracks), albums and song/playlist link resolution (pinned by offline fixtures in tests/fixtures/qianqian; playlist keyword search is refused by the platform and parses to an empty result per upstream parity; artists stay unimplemented because the upstream artist flag is phantom). The LX Music JS bridge (feature `lx-js-bridge`, docs/LX_JS_BRIDGE.md) is implemented up to the provider wrapper layer: the JSON-lines envelope, an in-tree Node.js child-process engine (src/lx_js_engine.rs) and provider wrappers translating the `search`/`musicUrl`/`lyric` responses into musid-dli traits (src/lx_js_provider.rs, unit-tested against a fake engine; there is no online smoke for this feature). Loading a real user LX custom-source script and managing the process lifecycle is host-provided. The human test checklist covers the four QR login flows (docs/HUMAN_TEST_CHECKLIST.md). Remaining VoiceFox providers: Soda (deferred, CENC model), plus the LX engine end-to-end wiring (host-provided). All eleven native reqwest providers (NetEase, QQ Music, Kugou, Kuwo, Migu, Bilibili, Jamendo, Apple Music, 5sing, Qianqian, JOOX) are wired through one injectable transport layer (src/transport.rs): each provider holds a cloneable Http handle built from a ClientProfile, retry and backoff are centralized in that layer reusing the retry.rs classifiers, platform-specific signing/decryption and cookie whitelists stay provider-side, and the MockTransport seam makes the provider HTTP paths testable offline (design and per-slice migration status: docs/integration/TRANSPORT_DESIGN.md). Error, auth and registry semantics are unified on the M2 core: errors carry a stable ErrorCategory plus structured, credential-free metadata (provider id, retryability, user hint) through a non-destructive extension root-exported as Error/ErrorCategory/ErrorDetail/Result and never holding cookies, tokens or signature parameters; sessions are multi-account (provider + account dual keys) with a seven-state auth status, import/export/refresh/revoke/expiry semantics and corrupt-file quarantine that never overwrites an existing quarantine copy; and the registry exposes unregistration, live capability queries, version/priority/auth-facet/supported-quality descriptors, duplicate-registration conflict policy and health snapshots that reset when an id fully leaves the registry (design and landing records: docs/integration/AUTH_REGISTRY_DESIGN.md). The M6 resource capabilities are landed on top of this core: an always-compiled artwork resolver trait with the twelfth registry slot and a local-cover-backed implementation (optional artwork-local feature), a domain-split cache (positive, negative, expiry and session-related results, all bounded), explainable match scoring with per-part breakdowns, explicit confidence and version-difference penalties pinned by a fixture matrix, five-class provider health semantics (unreachable/rate-limited/auth-invalid/maintenance/unknown) with non-sensitive counters, aggregated search with pagination continuation, cancellation handles and typed per-source errors, a resolve quality chain with actual-quality fallback records and structured fallback consumption, unified lyrics layering (original/translation/romanization/word-timed/plain lines) feeding the new lyrics cache with negative caching and expiry windows (the lyrics-cache feature plus the gate/producer aggregate selectors), and the audited lyrics-helper dependency decision (design and landing records: docs/integration/RESOURCE_DESIGN.md).

## Cargo features

- default = local + lyrics + session-file
- local = lofty metadata + walkdir scanning
- lyrics = offline parsing/generation/decryption facade; network search disabled
- lyrics-search = opt-in concurrent lyrics search across Netease, QQ, Kugou, Soda Music, LRCLIB and AMLL TTML DB
- session-file = atomic, permission-restricted provider session persistence
- download = engine core: HTTP range/multipart fetch with retry and per-chunk stall detection, candidate CDN fallback with the NetEase node rewrite, size/MD5 integrity gates, atomic .part staging (no byte-level resume, same as upstream), tag/lyric finish; task orchestration and UI stay in the VoiceFox host
- source-youtube-music = optional RustyPipe provider (GPL-3.0); requires a dedicated cache directory; use RustyPipeProvider::new_with_botguard when the helper is not on PATH
- source-netease = optional native NetEase provider (AES EAPI search, stream URL resolution with quality fallback, lyrics, cookie session, QR login, playlists, albums, artists, charts and link resolution; parsing pinned by offline response fixtures in tests/fixtures/netease)
- source-qqmusic = optional native QQ Music provider (zzc-signed lyrics, unsigned musicu.fcg search/detail/vkey resolution, M500-M800-Q000-F000-AI00 quality ladder, playlists, albums, charts, link parsing, QQ scan login, cookie session status; parsing pinned by offline response fixtures in tests/fixtures/qqmusic; WeChat login and QRC decryption pending)
- source-kugou = optional native Kugou provider (unsigned search, KRC lyrics decryption with word timing and language metadata, QR scan login, login-gated signed v5 stream URLs; parsing pinned by offline fixtures in tests/fixtures/kugou; collections pending)
- source-kuwo = optional native Kuwo provider (anonymous search, N_MINFO quality parsing, mobile 128k/320k stream URLs with placeholder rejection, web-signed playUrl whose Secret-header signing is tried first for lossless/HiRes requests with mobile fallback, yeelion-XOR GB18030 lyrics with word-timed lrcx decoding (fixture-verified only), playlists, charts, albums, song/playlist share-link resolution (song links fetch metadata only) and cover URL resolution over a two-tier fallback; parsing pinned by offline fixtures in tests/fixtures/kuwo; login, user playlists and artists pending)
- source-migu = optional native Migu provider (signed search, MRC word-timed lyrics via TEA containers, LRC/TRC fallbacks, anonymous stream resolution with obfuscated H5 strategy endpoint, playlists, charts (rank-index catalogue plus board songs, live-verified anonymously), albums over the anonymous queryAlbumSong track list (no album-detail endpoint upstream: metadata derived from the first track plus totalCount); parsing pinned by offline fixtures in tests/fixtures/migu; login and collections pending)
- source-bilibili = optional native Bilibili provider (WBI-signed search and DASH audio, BV/av reference expansion, QR login, login-gated favorites, charts over four boards on three unsigned endpoints plus the WBI-signed ranking/v2 board: fixture-verified, live path unverified; parsing pinned by offline fixtures in tests/fixtures/bilibili; no lyric API exists)
- source-jamendo = optional native Jamendo provider (CC catalog, x-jam-call SHA1 signing, search with embedded stream URLs, lossless-first; parsing pinned by offline fixtures in tests/fixtures/jamendo; container endpoints hang anonymously and stay unsupported)
- source-apple = optional native Apple Music provider (JWT bootstrap from the web bundle, signed search, 30-second preview streams only: full tracks are DRM, plain-text lyrics, album/playlist containers; parsing pinned by offline fixtures in tests/fixtures/apple)
- source-fivesing = optional native 5sing provider (unsigned search, three-tier stream URLs with backups, LRC lyrics via song metadata, playlist metadata; parsing pinned by offline fixtures in tests/fixtures/fivesing; track lists are JS-rendered and unsupported)
- source-qianqian = optional native Qianqian provider (91q.com; signed search, tracklink rate ladder with anonymous full files for free tracks and honest NotFound for VIP-gated ones, plain LRC lyrics, playlist categories/lists/detail, albums, song/playlist/album link parsing; parsing pinned by offline fixtures in tests/fixtures/qianqian; playlist keyword search is platform-refused and parses to an empty result, artists unimplemented: the upstream artist flag is phantom)
- source-joox = optional native JOOX provider (OpenJOOX web API: signed search, encrypted song-id stream URLs, plain LRC lyrics via JSONP, playlist search (parses to an empty result per upstream parity), playlist/album containers, song/playlist/album link resolution; parsing pinned by offline fixtures in tests/fixtures/joox; no login face exists upstream)
- lx-js-bridge = optional LX Music JS custom-source bridge (JSON-lines envelope over stdio, in-tree NodeJsEngine child process, JsBridgeProvider wrappers for search/musicUrl/lyric; unit-tested against a fake engine; no online smoke: end-to-end wiring with a real user script is host-provided)

## Transport injection (0.2.1)

Every provider's `with_transport(Http)` constructor is public: hosts inject
their own proxy/timeout budget through a `ClientProfile`, or a fully custom
`Transport` implementation via `Http::new`. See the `src/transport.rs` module
docs for the composition sketch.

## NetEase provider quick start

```rust,no_run
use musid_dli::{source_netease::NeteaseProvider, ProviderRegistry};

let provider = NeteaseProvider::new();
let mut registry = ProviderRegistry::new();
provider.register(&mut registry);
```

Run a live, read-only connectivity smoke test per module with `cargo run --features source-netease --example netease_smoke [MODULE...]`. Modules: `search track stream lyrics playlist chart album artist link auth user` (default: `search track stream lyrics`). The smoke test never downloads or plays audio; `auth` only generates a QR key and polls the status once, and `user` skips gracefully when no session cookie is configured. QQ Music has the equivalent `qqmusic_smoke` (`search track stream lyrics playlist chart album link auth wechat user`) behind `source-qqmusic`; anonymous runs are refused playable stream URLs by QQ itself (module code 10006), and `auth`/`wechat` render the QR images as data URLs then poll once. Kugou has `kugou_smoke` (`search lyrics playlist chart artist stream auth user`) behind `source-kugou`; the stream module reports SKIPPED for anonymous sessions because Kugou serves no URLs without login. Kuwo has `kuwo_smoke` (`search lyrics stream playlist link cover`) behind `source-kuwo`; the stream module requests lossless (web-signed playUrl first, mobile fallback) and walks the first search hits because paid tracks resolve to rejected placeholders. Migu has `migu_smoke` (`search lyrics stream playlist chart album`) behind `source-migu`; anonymously only PQ (128k) is served and the resolved quality reflects that. Jamendo and Apple Music each have their own smoke (`jamendo_smoke`, `apple_smoke` with modules `search stream lyrics album playlist link`); 5sing has `fivesing_smoke` (`search stream lyrics playlist link`); Qianqian has `qianqian_smoke` (`search stream lyrics playlist album link`, plus the optional `playlist_search` module that records the platform's live refusal) behind `source-qianqian`; the stream module walks the search hits because VIP tracks resolve to NotFound anonymously.

Required checks: cargo build --no-default-features, cargo test --no-default-features, cargo test.

See docs/VOICEFOX_AUDIT.md, docs/DEPENDENCY_AUDIT.md, docs/MIGRATION.md, docs/SOURCE_QQ_MUSIC_AUDIT.md, docs/PROVIDER_EVALUATION.md, docs/HUMAN_TEST_CHECKLIST.md and docs/IMPLEMENTATION_STATUS.md.
